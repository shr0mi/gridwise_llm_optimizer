 GridWise LLM — BUP CSE Fest 2026 Preliminary: Full Build Plan

 Context

 What we're building: one publicly-deployed HTTP service with exactly two endpoints — GET /health and POST /optimize-energy — for the BUP CSE Fest 2026 online preliminary (4-hour window, 7:00–11:00 PM). It receives a
 24-hour campus energy scenario plus 1–3 natural-language operator notes, uses an LLM to convert those notes into machine-checkable structured directives, validates them deterministically, applies them to a cost-minimizing
 24-hour battery/solar/grid schedule, and returns both the interpretation and the schedule.

 Why this shape: the rubric (100 pts, automated) is pipeline-scored, not cost-scored. 50 of 100 points are interpretation + downstream application; only 10 are optimization quality. A cheap schedule built on a wrong or
 unapplied directive scores zero for that case. So the plan optimizes for: exact schema compliance → correct note extraction → provably-correct directive application → optimal cost → reliability → docs/Docker.

 Validated finding (already done, this session): I implemented the LP formulation below and ran it against all 10 public sample cases using their ground-truth directives. It reproduces the organizer's total_cost_bdt exactly
 on 10/10 cases (delta 0.00). The optimizer is therefore a solved component — remaining risk is concentrated in LLM extraction, schema discipline, and deployment.

 Component decisions

 Stack: Python 3.11 · FastAPI + Pydantic v2 · uvicorn (uvloop/httptools) · scipy.optimize.linprog(method="highs") · google-genai async client (client.aio) + httpx.
 Rationale: HiGHS is a battle-tested exact LP solver and is already proven (above) to match organizer optimal; FastAPI gives async I/O for the LLM leg plus free request-schema validation → 400s for the API-contract points.

 Why LP and not greedy/DP: the problem is a pure linear min-cost flow over time (lossless battery, linear tariff). LP gives the global optimum, not an approximation — that is exactly the 10 optimization points, and it also
 guarantees hard directives (max_grid_window, reserves, no-charge/no-discharge) are satisfied by construction rather than by patching.

 LLM — Google Gemini (paid key).
 - Primary: gemini-2.5-flash, temperature=0, response_mime_type="application/json" + a strict response_schema (JSON-mode structured output) so the envelope and the directive_type enum are guaranteed well-formed. Set the
   thinking budget to 0 on the primary call — it removes seconds of latency and the extraction task does not need it.
 - Arbiter (disagreement only): gemini-2.5-pro, temperature=0, thinking enabled, shown both candidate interpretations and asked to pick. Fires on maybe 5–10% of requests, so it doesn't move p95.
 - Env vars: GEMINI_API_KEY (or GEMINI_API_KEYS comma-separated for the round-robin pool), GEMINI_MODEL, GEMINI_ARBITER_MODEL, LLM_TIMEOUT_S.
 - Pin the exact model IDs and SDK call signature at implementation time by checking the current google-genai docs — model aliases move.
 - Gemini has no Anthropic-style prompt-cache header; use implicit/explicit context caching if the static system block is large enough to qualify, otherwise rely on the note-level cache (§5), which is the bigger lever
   anyway.

 3. The optimizer (verified formulation)

 Decision variables per hour h∈0..23: g[h] grid, s[h] solar used, c[h] charge, d[h] discharge → 96 vars.

 minimize   Σ tariff[h] · g[h]

 s.t.  g[h] + s[h] + d[h] − c[h] = demand[h]                    (24 equalities)
       Σ_h (c[h] − d[h]) = 0                                     (end-of-day neutrality)
       E0 + Σ_{k≤h} (c[k] − d[k]) ≤ capacity                     (48 inequalities)
       E0 + Σ_{k≤h} (c[k] − d[k]) ≥ active_min[h]
 bounds: 0 ≤ g[h] ≤ grid_cap[h]      (∞ unless max_grid_window)
         0 ≤ s[h] ≤ eff_solar[h]     (solar × factor)
         0 ≤ c[h] ≤ charge_cap[h]    (0 in no_charge_window)
         0 ≤ d[h] ≤ discharge_cap[h] (0 in no_discharge_window)

 Directive→array construction (core/directives.py) builds eff_solar, active_min, charge_cap, discharge_cap, grid_cap from the validated directive list. Multiple directives of the same type compose by tightening: min() for
 caps, max() for reserves, multiplicative for solar factors.

 Post-solve hardening (core/optimizer.py) — this is where cases are silently lost, so do it precisely:
 1. Net out degeneracy. HiGHS may return c[h]>0 and d[h]>0 together (cost-neutral). Replace with net = c−d; charge if net>0, discharge if net<0, else idle. Safe: E-trajectory and balance are unchanged, rate limits can only
    relax.
 2. Snap epsilons. Values with |x| < 1e-9 → exactly 0.0; kill -0.0.
 3. Round-then-rederive (guarantees the judge's replay passes bit-exactly):
    - round battery_kwh and solar_used_kwh to 6 dp, flooring solar_used so it can never exceed eff_solar;
    - recompute battery_energy_after_kwh cumulatively from the rounded battery values → transitions exact, and force E[23] to land on initial_energy_kwh (absorb any residue into the last non-binding hour);
    - recompute grid_kwh = demand + charge − solar_used − discharge from the rounded values → the balance equation holds exactly, not within tolerance.
 4. Cap safety margin. Solve with grid_cap − 1e-6 so rounding can't push grid_kwh over a max_grid_window cap.
 5. Totals from the plan. total_grid_kwh = Σ grid_kwh, total_cost_bdt = Σ grid_kwh·tariff, peak_grid_kwh = max grid_kwh, all computed from the final rounded hourly_plan — the plan is the single source of truth (the rubric
    penalizes disagreement).

 Infeasibility ladder (status != 0) — never 500, never return an invalid plan:
 - Tier 1: re-solve dropping the lowest-confidence directive (extraction confidence ranking), one at a time.
 - Tier 2: re-solve with only base GridWise constraints.
 - Tier 3: analytic safe plan — battery idle all day (E ≡ E0, neutrality trivially holds), solar_used = min(eff_solar, demand), grid = demand − solar_used. Always feasible under base rules.
   Log which tier fired; still return 200 with a truthful plan_summary.

 4. The LLM interpretation path (the 25+25 points)

 4.1 Single call, all notes at once

 One request per scenario carrying all 1–3 notes → one round trip, not three. Gemini JSON mode with an explicit response_schema so the model cannot emit a malformed envelope or an out-of-enum directive_type.

 Response schema: {"interpretations":[{"note_index":int, "applies":bool, "directive_type":enum(6), "structured_adjustment":object|null, "explanation":str, "confidence":number}]} (confidence is internal only — stripped
 before the response).

 Gemini's schema support does not express per-type conditional shapes cleanly, so declare structured_adjustment with the union of optional fields (hours, factor, minimum_energy_kwh, max_grid_kwh) and let the deterministic
 guardrails in §4.4 enforce the exact per-type shape. Parse the JSON defensively (strip any stray code fences) before validating.

 4.2 System instruction (static block)

 Sent as system_instruction, containing: the 6 directive types and exact shapes; the end-exclusive window rule with 5 worked conversions; the factor = fraction remaining rule with 6 worked conversions ("80% reduction"→0.2,
 "drop to 25%"→0.25, "half"→0.5, "one-fifth"→0.2, "a third of normal"→0.33, "reduced by two-thirds"→0.33); percentage-of-capacity resolution; the "distractor ⇒ no_op" rule with examples; 12-hour↔24-hour clock mapping; the
 rule that it must never invent demand/tariff/battery values or new types.

 Few-shot examples derived from the 10 public cases but paraphrased and renumbered — the guide explicitly forbids hard-coding public wording, and hidden notes paraphrase. Include ~8 adversarial synthetics the public set
 doesn't cover:
 - overnight wrap: "no charging from 10 PM until 2 AM" → [0,1,22,23] (ascending!)
 - single hour: "cap grid at 150 kWh during the 7 PM hour" → [19]
 - all-day: "keep 60 kWh in reserve throughout the day" → 0..23
 - "until midnight" → end hour 24 → last hour 23
 - trailing "inclusive" phrasing ("through 9 PM" → [18,19,20,21])
 - a distractor that mentions energy but doesn't constrain today ("we're evaluating new solar panels next quarter") → no_op
 - two directives packed in one note → pick the single supported one (spec: each note maps to exactly one type)
 - a note referencing a percentage grid cap

 4.3 User message

 Notes (indexed) + the battery object + a compact hour table (hour/demand/solar/tariff). Battery is required for percentage-reserve resolution; the hour table helps ground "peak hours" phrasing. Explicit instruction: these
 are read-only facts, never to be modified.

 4.4 Guardrails (core/guardrails.py) — deterministic, runs on every LLM output

 1. directive_type ∈ allowlist, else → no_op.
 2. note_index ∈ [0, len(notes)); drop dupes (keep highest confidence); synthesize a no_op entry for any missing index; sort ascending. Output length must equal len(operator_notes).
 3. applies forced consistent: no_op ⇒ applies=false, structured_adjustment=null; anything else ⇒ applies=true and shape must validate, else demote to no_op.
 4. Hours: coerce to int, drop out-of-range, dedupe, sort ascending; empty ⇒ demote to no_op.
 5. factor clamp [0,1]; if the model returned a reduction fraction by mistake (detectable when the note contains "reduction"/"reduce by" and factor > 0.5 with matching complement) — do not silently flip; instead flag for
    the arbiter.
 6. minimum_energy_kwh: finite, ≥0, min(value, capacity_kwh).
 7. max_grid_kwh: finite, ≥0.
 8. No-invention check: the interpretation may not alter hours/battery; those are copied from the request object and never read back from the model.
 9. Reject NaN/Inf everywhere.

 Every demotion is logged with a reason (feeds the README's "known limitations").

 4.5 Rule-based cross-check + arbiter (accuracy lever, compliance-safe)

 A deterministic extractor (llm/fallback.py) parses time expressions, percentages, and kWh quantities with regex. It is never the sole interpreter — the LLM is always called and its guardrailed output is the default. The
 rule extractor is used for:
 - Disagreement detection. If rule and LLM differ on type or hours, fire one arbiter call (gemini-2.5-pro, temperature 0, both candidates shown, asked to pick and justify). Bounded: one extra call, only on disagreement.
 - Outage fallback. If the provider 5xxs / times out / circuit-breaker is open, use the rule output and mark it in logs. The guide explicitly permits a backup path; this keeps failure-rate points while the LLM remains the
   primary path under normal operation.

 This satisfies "hard-coded phrase matching as the sole interpreter — not compliant" while measurably lifting the paraphrase-robustness sub-score.

 4.6 Safe failure

 Malformed model output, refusal, timeout, or unparseable tool args ⇒ guardrails demote to no_op / rule fallback ⇒ still a valid 200 with a complete schedule. Never 500 on an LLM problem. Never invent a directive type.
 Never leak prompts, keys, or stack traces (rubric item 5 explicitly scores secret safety).

 8. Verification (how we prove it works)

 1. python tests/judge_sim.py --base-url <url> — POSTs all 10 public cases and checks, per case:
    - exactly one interpretation per note, in order; applies/directive_type/hours/numerics vs the pack's expected values;
    - hourly_plan has 24 unique hours; balance holds every hour; solar_used ≤ eff_solar; battery bounds/rates/transitions; E[23] == E0;
    - reserve / no-charge / no-discharge / grid-cap directives enforced hour by hour;
    - total_grid_kwh / total_cost_bdt / peak_grid_kwh recomputed from the plan;
    - cost_ratio = min(1, reference_cost / our_cost).
      Prints a rubric-shaped 0–100 estimate. Target: interpretation 10/10, validity 10/10, cost ratio 1.00 on all 10.
 2. Paraphrase suite — ~30 hand-written rewordings of the sample notes (different clock formats, fractions, synonyms, overnight windows, all-day, single-hour) checked against expected directives. This is the direct proxy
    for the 5 paraphrase-robustness points.
 3. Hostile input — truncated JSON, wrong types, 0 notes, 4 notes, 23 hours, duplicate hours, negative values, huge numbers, null battery fields → must return 400/422, never 500, never crash.
 4. Provider-failure drill — point the client at an invalid GEMINI_API_KEY / blackholed host → service must still return valid 200s via the fallback path.
 5. Load — scripts/loadtest.py at 100 and 500 concurrent → report p50/p95/p99 and failure rate.
 6. Docker fallback drill — on a clean machine: docker pull <tag> → documented docker run → /health → one public case. Exactly as the judge will do it.
 7. Clean-room README check — a teammate who didn't write it follows the README verbatim from a fresh clone. Any undocumented step loses points in category 7.

 9. Pitfalls this plan explicitly defends against

 - ❌ End-inclusive window parsing (the single most likely silent failure) → prompt rule + worked examples + paraphrase suite.
 - ❌ factor = reduction instead of remaining → explicit rule, 6 worked examples, arbiter flag.
 - ❌ Percentage reserves unresolved (SAMPLE-03) → battery object in the prompt.
 - ❌ Missing a no_op entry for a distractor → guardrail synthesizes entries so output length always equals note count.
 - ❌ Correct extraction, unapplied directive → directives feed the LP as hard constraints, then the self-validator replays them.
 - ❌ Totals disagreeing with hourly_plan → totals derived from the final rounded plan.
 - ❌ Float drift breaking balance / neutrality → round-then-rederive, exact E[23] = E0.
 - ❌ 500s or stack traces on bad input → global handlers + tiered fallbacks; secrets redacted.
 - ❌ Deploy discovered broken at 3:50 → deploy at 0:15.
 - ❌ Render free-tier cold start during judging → paid always-on instance + external uptime pinger.
 - ❌ Gemini safety-filter blocking a benign note → set the safety thresholds to the most permissive allowed and treat a blocked/empty candidate as a fallback trigger, not a crash.
 - ❌ Secrets in repo/image → .env.example with names only, .gitignore, runtime-only env vars (set in the Render/Railway dashboard, never in the image), image scanned before push.
